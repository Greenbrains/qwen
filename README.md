# 🧭 tutu-travel-agent v2 — агент-туроператор на Яндекс AI Studio + Tutu MCP

Консольный ИИ-агент, который ищет билеты и отели через **MCP-сервер Туту**
(`https://mcp.tutu.ru/mcp`) и даёт рекомендации по путешествиям. Работает на
**Yandex AI Studio** (OpenAI-совместимый API). Спроектирован как основа
**мультиагентной системы**: оркестратор пишет системные промпты агентам-
исполнителям, у каждого исполнителя — свой набор навыков и инструментов.

Основной принцип: **данные отделены от кода**. Промпты — в YAML, предметное
знание — в markdown-навыках, секреты — в `.env`, описание MCP-сервера — отдельным
документом.

---

## 🆕 Что изменилось в v2 (итог ревизии кода)

### 1. Экономия токенов — главный фикс
- Раньше **все 16 инструментов Туту** с полными JSON-схемами инжектились в поле
  `tools` на **каждой** из ≤25 итераций (`get_tools_as_functions()`), а
  статический `tutu_tools.py` при этом вообще не использовался (мёртвый код).
- Теперь MCP подключается **прокси-инструментом** `tutu_call(tool, args_json)`
  (режим `proxy`). Список инструментов Туту живёт в системном промпте одной
  короткой таблицей. Экономия на схемах инструментов — **~90%** за диалог.
- Добавлен **учёт токенов** (`Agent.usage`): prompt/completion/total за сессию,
  вывод в консоль и в `log.txt`.
- В навыке `touragent` и в описании сервера — явные правила экономии
  (`view="compact"`, не звать плейбуки без нужды, не дублировать поиски).

| Схемы инструментов Туту | на 1 шаг | за диалог ~8 шагов |
| :--- | ---: | ---: |
| v1.3 (expand, 16 схем) | ~2085 ток | ~16 700 ток |
| v2 (proxy, `tutu_call`) | ~190 ток | ~1 500 ток |

### 2. Мультиагентная архитектура (оркестратор + исполнители)
- Введён класс **`Agent`** — переиспользуемый исполнитель со своим
  `system_prompt`, набором инструментов и параметрами генерации.
- **`orchestrator.py`** — агент-оркестратор: декомпозирует запрос, выбирает
  навык, **сам пишет системный промпт исполнителю** (возвращает строгий JSON) и
  запускает его через `spawn_executor()`.
- **`SKILL_TOOLSETS`** (в `agent_tools.py`) — реестр «навык → разрешённые
  инструменты». Исполнитель получает только релевантный инструментарий
  (`filter_tools_for_skill`), что и снижает токены, и уводит модель от лишних
  вызовов.

### 3. Надёжность MCP-клиента
- Обработка `isError` из `tools/call` (бизнес-ошибка ≠ транспортная).
- Монотонные `id` запросов (были коллизии по `timestamp`).
- Авто-переустановка сессии при `400/401/404` и один повтор вызова.
- **TTL-кэш** `tools/list` вместо «вечного» кэша.
- Каталог инструментов сервера как markdown (`tools_catalog_markdown`).

### 4. Описание MCP-сервера
- Добавлен `tools/mcp/TUTU_MCP_SERVER.md` — «руководство» (server instructions)
  по назначению, жизненному циклу сессии, всем 16 инструментам, happy-path,
  экономии токенов и обработке ошибок.

## 🚀 Установка и запуск

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить YANDEX_API_KEY / YANDEX_FOLDER_ID

# одиночный агент
python agent.py

# мультиагентная система (оркестратор + исполнители)
python orchestrator.py
```

Требования: Python 3.12+, аккаунт Yandex Cloud AI Studio (роли
`ai.languageModels.user`, область `yc.ai.foundationModels.execute`).

## 🧩 Как устроена мультиагентность

```
Пользователь
     │
     ▼
Orchestrator.plan()  ──►  YandexGPT (JSON-mode)
     │  {skill, executor_system_prompt, task}
     ▼
spawn_executor(skill, executor_system_prompt)
     │   • инструменты = filter_tools_for_skill(skill)  ← только нужные
     │   • system_prompt = промпт оркестратора + дата + каталог Туту
     ▼
Agent.run(task)  ──►  цикл tool-calling  ──►  ответ + usage
```

- Оркестратор **не имеет** предметных инструментов — он «менеджер».
- Исполнитель **сам загружает** свой навык через `load_skill` и следует ему.
- Реестр `SKILL_TOOLSETS` задаёт, какие инструменты доступны навыку.

Добавить нового исполнителя = добавить навык в `.agents/skills/` + строку в
`SKILL.md` + (опц.) запись в `SKILL_TOOLSETS`. Код править не нужно.

## 🧰 Инструменты

| Инструмент | Назначение |
| :--- | :--- |
| `load_skill` | Загрузить навык или каталог навыков |
| `bash_execute` | Локальная bash-команда |
| `file_read` / `file_write` | Чтение / запись локальных файлов |
| `upload_file` / `download_file` / `list_files` | Files API Яндекса |
| `execute_code` | Python в Code Interpreter (артефакты → `output/`) |
| `generate_image` | Генерация изображений → `output/` |
| `web_search` | Веб-поиск Яндекса с источниками |
| **`tutu_call`** | **Прокси к MCP-серверу Туту** (авиа/жд/автобусы/отели/детали/чекаут) |

Вызов Туту:
```
tutu_call(tool="search_avia",
          args_json='{"origin":"Москва","destination":"Сочи","departure_date":"2026-08-15","passengers":2}')
```

Полный перечень инструментов Туту и их поля — в
`tools/mcp/TUTU_MCP_SERVER.md` и в системном промпте (живой каталог с сервера).

> При необходимости можно вернуться к «широкому» режиму (по функции на каждый
> MCP-инструмент): `create_all_tools(..., mcp_mode="expand")`. Это дороже по
> токенам и оставлено для отладки/совместимости.

## 🐛 Troubleshooting

| Симптом | Решение |
| :--- | :--- |
| MCP HTTP 400/401/404 | Сессия протухла — клиент сам переинициализируется и повторяет вызов |
| Инструменты Туту не видны | Проверьте `TUTU_MCP_URL`, доступность `mcp.tutu.ru`, лог `MCP initialize` |
| Пустой ответ модели | Обрабатывается «пинком» из `system.yaml`; смотрите `log.txt` |
| Обрыв длинных ответов | Увеличьте `generation.max_tokens` / `max_iterations` в `system.yaml` |
| Дорого по токенам | Убедитесь, что `mcp_mode="proxy"` (по умолчанию), а не `expand` |
