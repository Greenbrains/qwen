# 🧭 Multi-Agent System v3.0 — оркестратор + специалисты на Yandex AI Studio

Мультиагентная система на **Yandex AI Studio** (OpenAI-совместимый API).
Оркестратор («менеджер») маршрутизирует запрос к одному из
специализированных агентов-исполнителей. Каждый исполнитель имеет свой навык
(skill) и ограниченный набор инструментов. Туристический агент ходит в
**MCP-сервер Туту** (`https://mcp.tutu.ru/mcp`).

Главный принцип: **данные отделены от кода** — промпты в YAML, знания в
markdown-навыках, секреты в `.env`.

---

## 🆕 Что нового в v3.0 (оптимизация)

Ревизия выявила, что при переходе от одиночного агента к мультиагенту были
потеряны учёт токенов и устойчивость, а история диалога раздувала контекст.
Исправлено:

| Область | Было (v2.3) | Стало (v3.0) |
| :--- | :--- | :--- |
| **Учёт токенов** | Отсутствовал | `UsageTracker`: токены по каждому агенту + итог сессии, вывод в консоль и `usage`-отчёт |
| **История** | Одна общая, с чужими system-промптами → раздувание | **Отдельная история на каждого агента**, без чужих system |
| **Роутинг** | keyword → всегда LLM-вызов | **keyword → sticky → LLM** (LLM только как резерв) |
| **Липкость** | Нет | Уточнения продолжают текущего агента без LLM-роутинга |
| **Пустой/обрезанный ответ** | Не обрабатывался | «Пинки» как в одиночном агенте |
| **MCP в билдере** | Заглушка (`mock_initialized`) | Реальный `SyncMCPClient` |
| **`general`-агент** | Получал все инструменты | Лёгкий набор без дорогого `tutu_call` |

**Экономия токенов достигается тремя рычагами:**
1. LLM-роутинг вызывается редко (keyword + sticky перехватывают большинство).
2. Каждый агент видит только свою короткую историю, а не общий «котёл».
3. Инструменты фильтруются под навык (`SKILL_TOOLSETS`), MCP в режиме `proxy`.

## 🚀 Установка и запуск

```bash
pip install -r requirements.txt
cp .env.example .env       # заполнить YANDEX_API_KEY / YANDEX_FOLDER_ID

python main.py
Требования: Python 3.12+, аккаунт Yandex Cloud AI Studio (роль
ai.languageModels.user, область yc.ai.foundationModels.execute).

Переменные окружения (.env)
YANDEX_API_KEY=...
YANDEX_FOLDER_ID=...
YANDEX_MODEL=yandexgpt/latest      # опционально
```

🧩 Как работает система
Пользователь
     │  запрос
     ▼
Orchestrator._route()
     ├─ 1) keyword  ── есть триггер? → агент          (бесплатно)
     ├─ 2) sticky   ── короткое уточнение? → тот же   (бесплатно)
     └─ 3) LLM      ── резерв, 1 короткий вызов        (дорого, редко)
     │
     ▼
Orchestrator._get_agent()  ── кэш агентов (собирается 1 раз)
     │
     ▼
Agent.run(запрос, история_этого_агента)
     │  цикл tool-calling → фильтрованные инструменты
     ▼
ответ + токены (UsageTracker) → лог/консоль
Оркестратор не имеет предметных инструментов — он менеджер.
История хранится по каждому агенту (_histories[agent_name]), поэтому переключение между агентами не тащит чужой контекст и не раздувает токены.
Агенты кэшируются и переиспользуются между ходами.
Добавить нового специалиста
Создать навык .agents/skills/<name>/<name>.md (или <name>.md).
Добавить строку в AGENTS_CONFIG в main.py.
(Опц.) Прописать инструменты навыка в SKILL_TOOLSETS (agent_tools.py).
(Опц.) Ключевые слова в _KEYWORD_ROUTES (orchestrator.py) — чтобы роутинг был бесплатным.
Код движка править не нужно.

## 🧰 Инструменты

Инструмент	Назначение
load_skill	Загрузить навык / каталог навыков
bash_execute	Локальная bash-команда
file_read / file_write	Чтение / запись локальных файлов
upload_file / download_file / list_files	Yandex Files API
execute_code	Python в Code Interpreter (артефакты → output/)
generate_image	Генерация изображений → output/
web_search	Веб-поиск Яндекса с источниками
tutu_call	Прокси к MCP-серверу Туту (авиа/жд/автобусы/отели)
Вызов Туту (единый прокси, режим proxy — экономия ~90% токенов на схемах):

tutu_call(tool="search_avia",
          args_json='{"origin":"Москва","destination":"Сочи","departure_date":"2026-08-15","adults":2}')
Полный перечень полей Туту — в tools/mcp/TUTU_MCP_SERVER.md и в системном
промпте (живой каталог с сервера).

## 📊 Учёт токенов

Учёт токенов вернулся из одиночного агента и стал детальнее:

После каждого хода в консоль: 🎫 Токены [agent]: +N | сессия: M.
Команда usage — таблица по агентам в любой момент.
При выходе — итоговый отчёт за сессию.
В log/agent.log (DEBUG) — построчный TOKENS [agent] prompt/completion/total.
Пример итогового отчёта:

## 📄 Логи

Поток	Уровень	Что пишет
Консоль	INFO	Роутинг, итерации, вызовы инструментов, токены за ход
log/agent.log	DEBUG	Полный трейс: размышления, результаты, TOKENS
Лог пишется в режиме дозаписи (mode="a"). Для чистой диагностики очищайте
log/agent.log между прогонами.

## 🐛 Troubleshooting

Симптом	Решение
MCP HTTP 400/401/404	Сессия протухла — клиент переинициализируется и повторяет вызов
Инструменты Туту не видны	Проверьте доступность mcp.tutu.ru, лог MCP initialize в билдере
Роутинг мимо	Добавьте ключевые слова в _KEYWORD_ROUTES
Дорого по токенам	Проверьте, что LLM-роутинг срабатывает редко (лог 🧭 LLM-роутинг); MCP в режиме proxy; у general лёгкий набор инструментов
Пустой ответ модели	Обрабатывается «пинком» в Agent.run; смотрите log/agent.log
