# 🤖 ft_assistant2026 — AI-агент на Яндекс AI Studio

Консольный агент с tool-calling, системой навыков (Skills) и автоматическим
сохранением артефактов. Работает через OpenAI-совместимый API Яндекс AI Studio.

Главный принцип архитектуры — **данные отделены от кода**:
промпты живут в YAML, предметное знание — в markdown-навыках, секреты — в `.env`.
`agent.py` — чистый движок без «читерства» и подсказок под конкретные задачи.

---

## 💡 Ключевые идеи

1. **Данные отделены от кода.** Системный промпт, запрос-самопрезентация,
   сообщения-пинки и параметры генерации — в `.agents/prompts/system.yaml`.
   Поведение агента меняется правкой YAML, без правок Python.
2. **Навыки — это markdown.** Добавление навыка = новая папка в
   `.agents/skills/` + строка в каталоге `SKILL.md`. Код агента не меняется.
3. **Никакого «читерства».** Системный промпт не знает имён навыков, разделов
   и рецептов. Агент сам выбирает навык из каталога и следует его тексту буквально.
4. **Схемы инструментов генерируются автоматически.** Декоратор `@tool` в
   `tools.py` через `inspect` собирает JSON-схему из имени функции, docstring
   и type hints (`Annotated` — для описания параметров).
5. **Артефакты приземляются сами.** Файлы из Code Interpreter и сгенерированные
   изображения автоматически скачиваются из Files API в папку `output/`.

## 🎮 Режимы работы

| Ввод | Что происходит |
|---|---|
| Обычный текст | Агент выбирает навык/инструменты и выполняет задачу |
| Пустой Enter | Самопрезентация + генерация серого кота (проверка текста, tool-calling и сохранения в `output/`) |
| `exit` / `quit` / `выход` | Завершение работы |

## 🧰 Инструменты

| Инструмент | Назначение |
|---|---|
| `load_skill` | Загрузить навык по имени или каталог навыков (без аргумента) |
| `bash_execute` | Выполнить bash-команду локально |
| `file_read` / `file_write` | Чтение / запись локальных файлов |
| `upload_file` / `download_file` | Загрузка / скачивание файлов в Files API |
| `list_files` | Список файлов в облачном хранилище |
| `execute_code` | Python в изолированном контейнере (Code Interpreter); артефакты → `output/` |
| `generate_image` | Генерация изображений; файл автоматически → `output/` |
| `web_search` | Веб-поиск через встроенный tool Яндекса, с источниками (`url_citation`) |
| `use_mcp_server` | Подключение внешних сервисов через MCP |

### Как добавить свой инструмент

```python
from typing import Annotated
from tools import tool

@tool
def my_tool(query: Annotated[str, "Описание параметра для модели"]) -> str:
    """Описание инструмента — попадёт в JSON-схему для модели."""
    ...
```

Затем зарегистрируйте функцию в `create_all_tools()` — схема соберётся сама.

## 📚 Навыки (Skills)

Навык — markdown-инструкция с рабочим процессом, которой агент следует буквально.
Каталог `SKILL.md` — роутер: агент читает его, выбирает навык по колонке
«когда использовать» и загружает через `load_skill`.

| Навык | Что умеет |
|---|---|
| `cloudru-vm` | ВМ Cloud.ru: жизненный цикл, диски, сети, security groups, SSH/SCP |
| `cloudru-account-setup` | Настройка аутентификации Cloud.ru (env-переменные) |
| `browser-use` | Браузерная автоматизация: клики, формы, скриншоты, туннели |
| `marketingskills` | Маркетинг: контекст продукта, конкурентный ландшафт (XLSX), копирайтинг, SEO |

### Как добавить навык из маркетплейса Cloud.ru

1. Откройте страницу навыка, **F12 → Console**, введите `allow pasting`.
2. Вставьте скрипт извлечения (см. `getskill.md`) — он соберёт текст и положит в буфер.
3. Очистите текст (меню, цены, номера строк), переведите, оформите в markdown.
4. Создайте `.agents/skills/<имя>/<имя>.md`.
5. Добавьте строку в таблицу `.agents/skills/SKILL.md`.

Код агента править не нужно.

## 🔁 Как устроен цикл агента

1. Сообщение пользователя + системный промпт (YAML + живой каталог навыков).
2. Запрос в ЯндексGPT со схемами инструментов (`tool_choice=auto`).
3. Разбор `finish_reason`:
   - `tool_calls` — выполнить инструменты, результаты в историю, следующая итерация;
   - `length` — ответ обрезан: попросить модель продолжить с места остановки;
   - `stop` + пустой текст — аномалия: «пинок» сообщением из YAML;
   - `stop` + текст — финальный ответ пользователю.
4. Защита от зацикливания: `generation.max_iterations` (по умолчанию 25).

Code Interpreter итеративен: если код упал с ошибкой, модель видит traceback
и чинит код на следующей итерации (проверено на реальном запуске).

> верни Markdown-ссылку на файл из `output/` и резюме из 3–5 пунктов.

Результат: `output/competitors_analysis_<id>.xlsx` + резюме с источниками.

## 🐛 Troubleshooting

| Симптом | Причина / решение |
|---|---|
| `403 RBAC: access denied` при скачивании навыка по API | Маркетплейс закрыт авторизацией — извлекайте текст через браузер (F12), см. раздел выше |
| Агент «замолчал» (пустой ответ) | Обрабатывается автоматически пинком; смотрите `log.txt` → `TOKEN USAGE` |
| Длинные задачи обрываются | Увеличьте `generation.max_tokens` / `max_iterations` в `system.yaml` |
| `SyntaxError` в контейнере | Нормально: модель увидит traceback и исправит код на следующей итерации |

## 📎 Замечания

- Контейнер Code Interpreter **изолирован от сети**: данные из интернета
  добываются `web_search` и передаются в код готовыми значениями.
- Секреты никогда не выводятся в чат и логи консоли.
- Имена файлов в ответах агента — только те, что вернули инструменты
  (формат `output/<имя>_<id>.<ext>`), без выдумывания и заглушек.
