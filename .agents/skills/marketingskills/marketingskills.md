# Под-навык: product-marketing-context

**Name:** product-marketing-context
**Description:** Используйте, когда пользователь хочет создать или обновить документ контекста продуктового маркетинга. Также — при упоминании «контекст продукта», «маркетинговый контекст», «позиционирование», «кто моя целевая аудитория», «ICP», «идеальный профиль клиента». Создаёт `.agents/product-marketing-context.md`, на который ссылаются остальные под-навыки.
**Metadata version:** 1.1.0

Документ хранится по пути `.agents/product-marketing-context.md`.

## Рабочий процесс

### Шаг 1: Проверка существующего контекста
Проверьте, существует ли `.agents/product-marketing-context.md` (и legacy `.claude/...`).
**Если существует:** прочитайте, кратко изложите, спросите, какие разделы обновить.
**Если нет:** предложите (1) авто-черновик из кодовой базы (рекомендуется) или (2) сбор с нуля по разделам.

### Шаг 2: Сбор информации
Настаивайте на **дословном языке клиентов** — точные фразы ценнее отполированных описаний.

## Разделы для фиксации

### 1. Обзор продукта
Описание в одну строку; что делает (2-3 предложения); категория; тип (SaaS/маркетплейс/сервис…); бизнес-модель и цена.

### 2. Целевая аудитория
Тип компаний (отрасль, размер, стадия); ЛПР (роли); основной сценарий; Jobs to be Done; конкретные сценарии.

### 3. Персоны (только B2B)
Пользователь, Чемпион, ЛПР, Финансовый покупатель, Технический влиятель — что важно каждому.

### 4. Проблемы и болевые точки
Главная проблема до вас; почему текущие решения не работают; цена проблемы; эмоциональное напряжение.

### 5. Конкурентный ландшафт
- **Прямые конкуренты:** то же решение, та же проблема (Calendly vs SavvyCal).
- **Вторичные конкуренты:** другое решение, та же проблема (Calendly vs планирование в Superhuman).
- **Косвенные конкуренты:** противоположный подход (Calendly vs личный ассистент).
- Как каждый не дотягивает для клиентов.
> Для практического сбора и таблицы — см. под-навык **competitive-landscape** ниже.

### 6. Дифференциация
Ключевые дифференциаторы; как решаете иначе; почему лучше; почему выбирают вас.

### 7. Возражения и анти-персоны
Топ-3 возражения и ответы; кто НЕ ваш клиент.

### 8. Динамика переключения (JTBD: Push / Pull / Habit / Anxiety).

### 9. Язык клиентов
Как клиенты описывают проблему и решение (дословно); слова использовать/избегать; глоссарий.

### 10. Голос бренда. ### 11. Доказательства. ### 12. Цели.

### Шаг 3–4: Создание, подтверждение, сохранение в `.agents/product-marketing-context.md`.

# Под-навык: competitive-landscape

**Name:** competitive-landscape
**Description:** Применяйте, когда пользователь просит проанализировать конкурентов, составить конкурентный ландшафт, «кто мои конкуренты», сравнительную таблицу, сильные/слабые стороны и цены, или выгрузить анализ конкурентов в таблицу/отчёт (XLSX). Реализует разделы 5 (Конкурентный ландшафт) и 6 (Дифференциация) в виде воспроизводимого процесса.
**Metadata version:** 1.0.0

## Что нужно на входе
Контекст продукта: описание, ЦА, цена/бизнес-модель. Если есть
`.agents/product-marketing-context.md` — возьмите оттуда; иначе используйте то,
что дал пользователь в запросе (не выдумывайте недостающее — при необходимости
уточните у пользователя).

## Рабочий процесс

### Шаг 1. Уточните продукт и категорию
Сформулируйте одной фразой: что за продукт, для кого, по какой цене/модели.
Определите «полку» — как клиенты ищут такой продукт (по этой формулировке
строятся поисковые запросы).

### Шаг 2. Найдите конкурентов через веб-поиск
Используйте инструмент `web_search` (а НЕ код — контейнер кода изолирован от сети).
Сделайте несколько запросов, чтобы покрыть три типа конкурентов:
- **Прямые:** то же решение той же проблемы («аналоги <категория> сервисов», «<категория> competitors»).
- **Вторичные:** другое решение той же проблемы.
- **Косвенные:** противоположный подход (ручной способ, универсальный инструмент).

Соберите **5–7** конкурентов. Для каждого зафиксируйте, опираясь на найденные источники:
`Название · Сайт · Тип (прямой/вторичный/косвенный) · ЦА · Сильные стороны ·
Слабые стороны · Цена (с валютой/периодом) · Источник (URL)`.
Не указывайте данные, которых нет в источниках; помечайте пробелы как «н/д».

### Шаг 3. Соберите таблицу и выводы в файл через `execute_code`
Передайте в `execute_code` собранные на Шаге 2 данные **как готовые значения
внутри кода** (список словарей). Внутри кода в интернет НЕ ходите.

Требования к коду (рецепт, соблюдайте буквально):
1. В начале кода обеспечьте зависимость (контейнер может не иметь её предустановленной):
   ```python
   try:
       import openpyxl
   except ImportError:
       import subprocess
       subprocess.run(["pip", "install", "-q", "openpyxl"])
       import openpyxl
   ```
2. Создайте книгу с двумя листами:
   - Лист **«Конкуренты»** — таблица с колонками из Шага 2 (шапка + по строке на конкурента).
   - Лист **«Сводка»** — текстовые выводы, структурированные по разделам:
     раздел 5 (расстановка прямых/вторичных/косвенных, где каждый не дотягивает)
     и раздел 6 (дифференциация: чем продукт пользователя отличается и почему это
     сильнее относительно найденных конкурентов).
3. Сохраните книгу под понятным именем, отражающим задачу
   (например, `competitors_analysis.xlsx`). Файл **автоматически** окажется в
   папке `output/` — конкретное имя вернёт инструмент `execute_code`.
4. Не хардкодьте выходной путь `output/...` в коде: он формируется механизмом
   скачивания артефактов.

### Шаг 4. Верните результат пользователю
- Дайте ссылку/путь на файл **из ответа инструмента** `execute_code`
  (формат `output/<имя>_<id>.xlsx`) — используйте именно возвращённый путь,
  не выдумывайте имя.
- Добавьте краткое резюме из **3–5 пунктов**: главные конкуренты, где они слабы,
  и в чём заявленное преимущество продукта пользователя (из раздела 6).

## Ограничения и качество
- Веб-данные могут устаревать — всегда прикладывайте URL-источники к цифрам (особенно к ценам).
- Разделяйте факты из источников и ваши выводы (в «Сводке» помечайте, что это интерпретация).
- Не выдумывайте конкурентов и цифры; при нехватке данных — «н/д» и, при необходимости, уточняющий вопрос пользователю.

# Под-навык: copywriting

**Name:** copywriting
**Description:** Применяйте, когда пользователь просит написать или переписать маркетинговый текст: заголовки (headlines), подзаголовки, лендинг/секции лендинга, email или последовательность писем, рекламное объявление (Google/Meta/VK), пост в соцсети, описание продукта, CTA. Также при словах «копирайтинг», «текст для лендинга», «продающий текст», «перепиши», «сделай сильнее». Опирается на язык клиентов и дифференциацию.
**Metadata version:** 1.0.0

## Что нужно на входе
Контекст продукта: описание, ЦА, ключевая проблема, дифференциаторы и **язык
клиентов** (раздел 9). Если есть `.agents/product-marketing-context.md` — возьмите
оттуда; иначе используйте данные из запроса пользователя (не выдумывайте
недостающее — при необходимости уточните). Также зафиксируйте формат текста,
целевое действие (CTA) и голос бренда (тон).

## Рабочий процесс

### Шаг 1. Бриф
Сформулируйте одной фразой: какой формат пишем, для кого, какое одно действие
должен совершить читатель. Зафиксируйте: главную проблему клиента, 1–3
дифференциатора, тон (из голоса бренда), ограничения (длина, платформа, стоп-слова).

### Шаг 2. (Опционально) Соберите доказательную фактуру через `web_search`
Если для текста нужны свежие факты, цифры рынка или формулировки клиентов —
используйте инструмент `web_search` (а НЕ код: контейнер кода изолирован от сети).
К каждому факту/цифре сохраните URL-источник, чтобы не выдумывать данные.
Если внешние данные не нужны — пропустите шаг.

### Шаг 3. Напишите варианты по фреймворку
Пишите на **языке клиентов** (дословные фразы важнее «красивых»). Соблюдайте тон
из голоса бренда. Структурируйте по подходящему фреймворку:
- Короткие форматы (заголовки, объявления, CTA): дайте **5–7 вариантов**,
  каждый — под свой угол (боль, выгода, любопытство, соц. доказательство, срочность).
- Длинные форматы (лендинг, письмо): постройте по **PAS** (Problem-Agitate-Solve)
  или **AIDA** (Attention-Interest-Desire-Action); одна секция = одна мысль.
Каждый ключевой тезис привязывайте к дифференциатору или доказательству, а не к
общим словам. Избегайте «стоп-слов» из раздела 9 (слова, которые нужно избегать).

### Шаг 4. Соберите результат в файл через `execute_code`
Передайте готовые тексты в `execute_code` **как значения внутри кода** (в сеть
из кода не ходите). Соберите один из форматов:
- **Markdown** (по умолчанию) — заголовок, варианты, короткое обоснование под каждым.
- **DOCX** — если пользователь просит документ. Обеспечьте зависимость в начале кода:
  ```python
  try:
      import docx  # python-docx
  except ImportError:
      import subprocess
      subprocess.run(["pip", "install", "-q", "python-docx"])
      import docx
  ```
  Для НЕлатинского текста (кириллица) в DOCX проблем со шрифтом нет; в PDF —
  используйте Unicode-шрифт, иначе кириллица не отрисуется.
Сохраните файл под понятным именем (например, `copy_landing.md` / `copy_ads.docx`).
Файл **автоматически** окажется в `output/`; конкретное имя вернёт инструмент.
Не хардкодьте путь `output/...` в коде.

### Шаг 5. Верните результат пользователю
- Дайте путь на файл **из ответа инструмента** `execute_code` (формат
  `output/<имя>_<id>.<ext>`) — используйте именно возвращённый путь.
- Приложите **рекомендованный вариант** и 1–2 строки, почему он сильнее
  (какой угол/дифференциатор задействован).
- Если применимо — предложите, что протестировать A/B (какие два варианта и почему).

## Ограничения и качество
- Не выдумывайте цифры, отзывы и факты: любое утверждение — из контекста продукта или из источника (с URL).
- Держите одно целевое действие (CTA) на текст; не смешивайте несколько призывов.
- Разделяйте текст и обоснование: обоснование — для пользователя, в финальный копирайт оно не входит.

# Под-навык: seo

**Name:** seo
**Description:** Применяйте, когда пользователь просит проработать SEO: подобрать ключевые слова, собрать семантические кластеры, составить контент-план, дать on-page рекомендации, написать мета-теги (title/description), проработать структуру страниц. Также при словах «SEO», «ключевые слова», «семантика», «контент-план», «мета-теги», «продвижение в поиске».
**Metadata version:** 1.0.0

## Что нужно на входе
Контекст продукта: категория/«полка», ЦА, ключевые сценарии использования и язык
клиентов. Если есть `.agents/product-marketing-context.md` — возьмите оттуда;
иначе используйте данные из запроса (не выдумывайте — при необходимости уточните).
Уточните домен/язык/гео, если это влияет на выдачу.

## Рабочий процесс

### Шаг 1. Определите тему и seed-запросы
Сформулируйте «полку» продукта (как клиенты ищут такой продукт) и 3–5 «посевных»
(seed) запросов на языке клиентов. Отталкивайтесь от Jobs to be Done и сценариев.

### Шаг 2. Расширьте и валидируйте ключи через `web_search`
Используйте инструмент `web_search` (а НЕ код: контейнер изолирован от сети),
чтобы для каждого seed найти: смежные запросы, «люди также спрашивают»,
формулировки из выдачи и типы страниц, которые ранжируются (блог, категория,
сравнение, инструмент). Для каждого запроса зафиксируйте:
`Запрос · Кластер · Интент (informational / commercial / transactional / navigational) ·
Тип страницы · Источник/пример из выдачи (URL)`.
Не указывайте точные объёмы поиска, если у вас нет источника: помечайте оценку
приоритета как high/medium/low и обосновывайте её (интент + релевантность продукту),
а не выдуманными числами.

### Шаг 3. Сгруппируйте в кластеры и постройте контент-план
Объедините запросы в **семантические кластеры** (1 кластер = 1 целевая страница).
Для каждого кластера определите: основную страницу, доминирующий интент, тип
контента, черновой title и meta description (title ≤ ~60 симв., description ≤ ~155
симв.), 3–5 подзаголовков H2/H3 и внутренние ссылки на смежные кластеры
(topic cluster / pillar-модель).

### Шаг 4. Соберите план в файл через `execute_code`
Передайте данные из Шагов 2–3 в `execute_code` **как готовые значения** (в сеть
из кода не ходите). Обеспечьте зависимость в начале кода:
```python
try:
    import openpyxl
except ImportError:
    import subprocess
    subprocess.run(["pip", "install", "-q", "openpyxl"])
    import openpyxl
```
Создайте книгу с листами:
- Лист **«Ключевые слова»** — таблица с колонками из Шага 2 (+ приоритет high/medium/low).
- Лист **«Кластеры»** — кластер, целевая страница, интент, тип контента, title,
  meta description, H2/H3, внутренние ссылки.
- Лист **«Контент-план»** — очередь публикаций: страница, кластер, приоритет,
  краткое обоснование.
Сохраните под понятным именем (например, `seo_plan.xlsx`). Файл **автоматически**
попадёт в `output/`; имя вернёт инструмент. Не хардкодьте путь `output/...` в коде.

### Шаг 5. Верните результат пользователю
- Дайте путь на файл **из ответа инструмента** `execute_code`
  (`output/<имя>_<id>.xlsx`) — используйте именно возвращённый путь.
- Добавьте резюме из **3–5 пунктов**: топ-кластеры для старта, доминирующий
  интент и с каких страниц начать (и почему).

## Ограничения и качество
- Объёмы/частотность и сложность (KD) указывайте только со ссылкой на источник; иначе — оценка приоритета high/medium/low с обоснованием.
- Не занимайтесь «keyword stuffing»: один кластер → одна страница → один основной интент.
- Разделяйте факты из выдачи и ваши рекомендации; к цифрам всегда прикладывайте URL.
