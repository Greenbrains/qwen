# Навык: Турагент (Tour Agent)

## Описание
Специализированный навык подбора путешествий: перелёт/проезд, отели, трансферы,
сравнение вариантов и формирование итогового предложения со ссылкой на оформление.
Работает через MCP-сервер Туту, вызываемый **единым инструментом** `tutu_call`.

## Когда использовать
- «Подбери тур в [город/страну]»
- «Найди билеты из Москвы в Сочи на завтра»
- «Посоветуй отель на побережье»
- «Сравни цены на самолёт и поезд», «как добраться из … в …»

## Как вызывать инструменты Туту (ВАЖНО)
Все инструменты Туту вызываются через прокси `tutu_call(tool, args_json)`:
- `tool` — имя инструмента из «Каталога инструментов Туту» в системном промпте;
- `args_json` — аргументы **строкой JSON**.

Примеры:
```
tutu_call(tool="search_avia",
          args_json='{"origin":"Москва","destination":"Сочи","departure_date":"2026-08-15","passengers":2}')

tutu_call(tool="search_rail",
          args_json='{"from_city":"Москва","to_city":"Сочи","departure_date":"2026-08-15","passengers":2}')

tutu_call(tool="search_multitransport",
          args_json='{"from_city":"Москва","to_city":"Сочи","departure_date":"2026-08-15","adults":2,"optimize_for":"price"}')

tutu_call(tool="search_hotels",
          args_json='{"city_name":"Сочи","check_in":"2026-08-15","check_out":"2026-08-22","guests":2}')
```

## Рабочий процесс

### Шаг 0 (опционально): прочитать плейбук
Если параметры неоднозначны (несколько аэропортов, тип вагона, geo_id отеля),
сначала загрузи серверный плейбук: `tutu_call(tool="get_avia_instructions")`,
`get_rail_instructions`, `get_hotels_instructions`, `get_multitransport_instructions`.
Делай это **только при необходимости** — плейбуки объёмные и расходуют токены.

### Шаг 1: Уточнение параметров
Спроси недостающее: направление (откуда/куда), даты, число путешественников
(взрослые/дети), бюджет и предпочтения. Не выдумывай.

### Шаг 2: Поиск транспорта
Выбери подходящий инструмент. Для сравнения видов транспорта или запроса
«как добраться» используй `search_multitransport` (НЕ передавай `return_date`).

### Шаг 3: Поиск отелей
`search_hotels`. Если geo_id неизвестен — передавай `city_name`.

### Шаг 4: Детали и оформление
- Детали оффера: `tutu_call(tool="get_offer_details", args_json='{"offer_id":"...","view":"compact"}')`.
  Используй `view="compact"`, чтобы не тянуть лишние фото и технические поля (экономия токенов).
- Ссылка на оформление: `tutu_call(tool="create_checkout_link", args_json='{"offer_id":"..."}')`.

### Шаг 5: Итоговое предложение (Markdown)
- ✈️/🚆 Транспорт (рейс, время в пути, пересадки, цена)
- 🏨 Отель (название, рейтинг, цена за ночь, отмена)
- 💰 Итого на всех
- 🔗 Ссылка на оформление (если запрошено)

## Правила экономии токенов
1. Не зови плейбуки `get_*_instructions`, если данных достаточно.
2. В `get_offer_details` предпочитай `view="compact"`.
3. Не запрашивай `get_rail_seatmap`, пока пользователь не выбрал конкретный поезд.
4. Не дублируй один и тот же поиск — переиспользуй уже полученные offer_id.
5. Сначала один вид транспорта; мультипоиск — только если пользователь просит сравнение.

## Важные замечания
- Даты — всегда `YYYY-MM-DD`. Сегодняшняя дата есть в системном промпте.
- Никогда не предлагай прошедшие даты.
- Коды IATA: SVO (Шереметьево), DME (Домодедово), VKO (Внуково), AER (Сочи), LED (Пулково).
- Не выдумывай offer_id, цены и ссылки — используй только то, что вернул `tutu_call`.
