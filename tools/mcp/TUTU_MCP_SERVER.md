# MCP-сервер Туту — описание и инструкция по использованию

> Этот документ — «руководство» (server instructions) для LLM-агента и людей.
> Он описывает назначение сервера `https://mcp.tutu.ru/mcp`, полный перечень
> инструментов, их параметры, стратегию вызова и правила экономии токенов.
> Держите его коротким и actionable: плохие инструкции хуже, чем их отсутствие.

---

## 1. Назначение

MCP-сервер Туту предоставляет агенту доступ к поиску и оформлению
путешествий: **авиа, ж/д (РЖД), автобусы, электрички, отели**, мультимодальные
маршруты «как добраться», детализация предложений и генерация ссылки на оплату.

Протокол: **MCP over Streamable HTTP** (JSON-RPC 2.0), версия
`2024-11-05`. Ответы могут приходить как `application/json`, так и
`text/event-stream` (SSE) — клиент обязан поддерживать оба формата.

---

## 2. Жизненный цикл сессии

1. `initialize` → сервер возвращает возможности и (опц.) заголовок
   `Mcp-Session-Id`. Сохраните его и шлите в каждом последующем запросе.
2. `notifications/initialized` (уведомление, ответ 202 Accepted — норма).
3. `tools/list` → актуальный перечень инструментов (источник истины).
4. `tools/call` → вызов инструмента.

Если сервер вернул `400/401/404` — сессия протухла: сбросьте `Mcp-Session-Id`
и переинициализируйтесь (клиент делает это автоматически и повторяет вызов один раз).

---

## 3. Каталог инструментов (16)

### Поиск (`search_*`)
| Инструмент | Назначение | Обязательные поля | Опциональные |
| :--- | :--- | :--- | :--- |
| `search_avia` | Авиабилеты между городами/аэропортами (IATA) | `origin`, `destination`, `departure_date` | `passengers` |
| `search_rail` | Ж/д билеты РЖД (плацкарт/купе/СВ/сидячий) | `from_city`, `to_city`, `departure_date` | `passengers`, `sort` |
| `search_bus` | Междугородние автобусы | `origin`, `destination`, `departure_date` | — |
| `search_etrain` | Пригородные поезда (электрички) | `origin`, `destination`, `departure_date` | — |
| `search_multitransport` | Мультимодальный «как добраться» (авиа+жд+бус+эл.) | `from_city`, `to_city`, `departure_date` | `adults`, `optimize_for` (`price`\|`time`). **НЕ передавать `return_date`** |
| `search_hotels` | Отели по городу/geo_id/координатам | `check_in`, `check_out` | `city_name`, `geo_id`, `guests` |

### Плейбуки (`get_*_instructions`) — без параметров
Возвращают подробную инструкцию сервера по домену. **Объёмные** — вызывайте
только при неоднозначности. Доступны: `get_avia_instructions`,
`get_rail_instructions`, `get_bus_instructions`, `get_etrain_instructions`,
`get_hotels_instructions`, `get_multitransport_instructions`.

### Детализация
| Инструмент | Назначение | Поля |
| :--- | :--- | :--- |
| `get_offer_details` | Детали оффера | `offer_id` (обяз.), `view` = `compact`\|`full` |
| `get_rail_seatmap` | Схема вагона РЖД | `offer_id` (обяз.), `car_number` |

### Действия / ресурсы
| Инструмент | Назначение | Поля |
| :--- | :--- | :--- |
| `create_checkout_link` | Ссылка на оформление | `offer_id` (обяз.), `passengers[]` |
| `fetch_resource` | Чтение справочника `tutu://…` | `uri` (напр. `tutu://dictionary/airports`) |

Формат дат — **`YYYY-MM-DD`**.

---

## 4. Рекомендуемый сценарий (happy path)

1. (опц.) `get_*_instructions` — если параметры неоднозначны.
2. `search_*` → получить список офферов и их `offer_id`.
3. `get_offer_details(offer_id, view="compact")` — детали выбранного оффера.
4. (жд, при выборе места) `get_rail_seatmap(offer_id, car_number)`.
5. `create_checkout_link(offer_id, passengers=[…])` — финальная ссылка.

---

## 5. Экономия токенов (важно для стоимости)

Ответы поиска и особенно плейбуков — крупные. Правила:

- **Не грузите все 16 схем инструментов в контекст модели.** Отдавайте модели
  один прокси-инструмент + короткий каталог (см. `tutu_tools.py`, режим
  `proxy`). Полные схемы берите с сервера через `tools/list` по требованию.
- **`view="compact"`** в `get_offer_details` по умолчанию — убирает фото и
  технические поля.
- **Плейбуки — по необходимости**, не «на всякий случай».
- **Кэшируйте `tools/list`** (TTL, напр. 300 с) — не дёргайте на каждом шаге.
- **Не дублируйте поиски** — переиспользуйте полученные `offer_id`.
- Для сравнения видов транспорта используйте `search_multitransport` **один**
  вызов вместо трёх раздельных `search_*`.

---

## 6. Обработка ошибок

- Ответ `tools/call` может содержать `isError: true` и текст в `content[].text`.
  Агент обязан отличать бизнес-ошибку (нет рейсов) от транспортной (HTTP/timeout).
- `soft-fail` в мультипоиске: часть `variants[]` может отсутствовать — покажите
  то, что есть, и сообщите, какие виды транспорта не найдены.
- Таймаут `tools/call` рекомендуется 120 с (поиск бывает долгим).

---

## 7. Заголовки запроса (reference)

```
Content-Type: application/json
Accept: application/json, text/event-stream
MCP-Protocol-Version: 2024-11-05
Mcp-Session-Id: <из ответа initialize>   # начиная со второго запроса
User-Agent: <имя-агента>/<версия>
```
