ВЗЯТО ОТСЮДА @deepseek-ai/dsh
Эта dshкоманда запускает профили продуктов: упорядоченные стопки слоев патчей из пакетов плагинов, находящиеся под собственными настройками пользователя. src/args.tsОна контролирует грамматику команд и src/bin.tsзагружает только выбранный исполнитель. Недопустимые команды, параметры из другого режима, ошибки конфигурации и сбои загрузки приводят к ненулевому коду завершения.

Режимы входа
Командование	Цель
dsh --profile <name>	Запустите именованный профиль в папке $DSH_HOME/profiles/<name>.
dsh --profile headless "job"	Запустите новую, сохраненную сессию, выведите окончательный ответ и завершите работу.
dsh web	Псевдоним --profile web.
dsh plugin --profile <name> <pnpm args>	Управляйте плагинами профиля, перенаправляя запросы в pnpm из каталога профиля.
В качестве каталога запуска используется корневая директория рабочей области по умолчанию. Профили webи headlessавтоматически инициализируются при первом использовании из поставляемых шаблонов; любой другой профиль необходимо создать с помощью dsh plugin.

Аргументы приложения
Программа запуска анализирует только свои собственные флаги и передает все, что следует за ними, загруженному профилю, где любой внедренный плагин приложения может анализировать общий неизменяемый снимок ( dsh-cmdline). Таким образом, флаги программы запуска идут первыми, и первый токен, который программа запуска не распознает, начинает передавать аргументы приложения:

dsh --profile web --port 8080       # --port belongs to the web app
dsh --profile tui --resume <id>     # example, assuming the tui profile is installed; --resume belongs to the terminal app
dsh --profile headless "run the tests"
dsh --profile web --help            # the web app's flags, not the launcher's
dsh --help                          # the launcher's own help
Профили
В каталоге профиля находятся package.json(зависимости плагинов, не входящие в основное дерево, плюс манифест профиля dsh.profileс его упорядоченным bundlesсписком) и cordis.patch.yml(собственный слой патчей пользователя).

Дерево строится над пустым корнем:

патчи каждого комплекта по dsh.profile.bundlesпорядку
затем профиль cordis.patch.yml, затем уровень главной страницы$DSH_HOME/cordis.patch.yml
затем --patchналожения
Сначала устанавливаются пакеты, указанные в dsh.profile.bundlesконфигурации, из установки dsh ( @deepseek-ai/dsh-base, @deepseek-ai/dsh-web-app, @deepseek-ai/dsh-headless), затем из собственного файла профиля node_modules, где pnpm устанавливает плагины, находящиеся вне дерева исходных файлов.

Используйте команду --dump-default-config`and` --dump-configдля проверки составленного дерева без его загрузки.

Справочник по поведению CLI содержит информацию о точном приоритете слоев, флагах, поведении при завершении работы, параметрах развертывания по умолчанию и выполнении исходного кода.

Разработка
Для запуска в производственной среде требуются собранные пакеты и артефакты фронтенда. Из корневой директории репозитория запустите команду pnpm run buildотдельно, затем используйте её pnpm dsh <args...>для запуска записи TypeScript и передачи всех аргументов; ссылка на выполнение исходного кода управляет контрактом разрешения модулей.
